# 講座スケジュール管理システム（仮称）
モジュール設計（React + Vite）

本ドキュメントは、  
**React（JavaScript）+ Vite**  
**React Router / Jotai（Atom） / TanStack Query / Axios**  
**Chakra UI**  
を前提としたモジュール設計を示す。

---

## 1. 設計方針

### 1.1 基本方針

- 画面（ルーティング）とドメインロジックを分離する
- 永続データは **TanStack Query** で管理する
- UI状態（トグル、選択状態）は **Jotai** を最小限で使用する
- API通信は **Axios を1箇所に集約** する
- 日付割当・採番などの複雑な処理は **純粋関数として分離** する
- 印刷機能は通常画面とは別の責務として扱う

## 3. レイヤー別役割

### 3.1 app/

アプリケーション全体の初期化と共通設定を担う。

- `App.jsx`  
  - ルートコンポーネント
- `router.jsx`  
  - React Router のルート定義
- `providers/`  
  - Chakra UI、TanStack Query などの Provider を集約
- `layout/`  
  - 共通レイアウト（ヘッダー、ナビ）
- `styles/`  
  - グローバルCSS、印刷用CSS

---

### 3.2 pages/

URL単位の画面コンポーネント。

- 画面構成のみを担当し、  
  **ビジネスロジックは features に委譲する**
- URLパラメータ取得、画面構成が主な役割

---

### 3.3 features/

ドメインごとの機能実装。

#### 共通ルール

- `api.js`  
  - Axios を使った CRUD 処理
- `queries.js`  
  - TanStack Query の `useQuery / useMutation` 定義
- `components/`  
  - 画面で使うUI部品
- `logic/`  
  - 純粋関数（副作用なし）

---

#### course

- 講座基本情報管理
- 休講日管理
- 印刷用ヘッダー／フッター管理

---

#### category

- 講義区分管理（例：Javaプログラミング実習）

---

#### lecture

- 講義マスタ管理
- 講義説明（detail）を含む

---

#### dayBlock

- 1日分の講義ブロック管理
- 区分＋講義並びのみを保持（タイトルなし）

---

#### schedule

- スケジュール並び順管理（D&D）
- 見出し（基礎編／応用編）管理
- 日付自動割当
- 休講日表示トグル対応

**logic/**
- `buildSchedule.js`  
  - 日付割当、休講日除外ロジック
- `numbering.js`  
  - 区分ごとの連番（①②…）付与
- `calendar.js`  
  - 曜日計算、土日判定

---

#### print

- 印刷専用モデル生成
- A4 PDF 出力用DOM構築

**logic/**
- `buildPrintModel.js`  
  - scheduleロジックを再利用し、印刷用構造に変換

---

### 3.4 components/

アプリ全体で再利用可能な汎用UI。

- ダイアログ
- ローディング
- エラー表示
- タイトル表示

---

### 3.5 lib/

外部依存や共通処理の集約。

- `api/axios.js`  
  - Axios インスタンス
- `query/`  
  - QueryClient 設定、queryKey管理
- `utils/`  
  - 日付処理、検証処理
- `constants/`  
  - ルーティング定数など

---

### 3.6 store/

Jotai Atom 定義。

- UI状態のみ管理
  - 休講日表示トグル
  - 印刷モードなど

---

## 4. 状態管理の指針

| 種別 | 管理方法 |
|---|---|
| 永続データ | TanStack Query |
| UI状態 | useState / Jotai |
| 並び順 | json-server + Query invalidate |
| 日付割当 | 表示時に計算（保存しない） |

---

## 5. 印刷機能の設計方針

- 印刷画面は `/print` ルートに分離
- `@media print` と `@page` を `print.css` に集約
- Chakra UI は補助的に使用し、  
  レイアウトはHTML/CSSを優先

---

## 6. 将来拡張を考慮したポイント

- TypeScript移行が容易な構造
- 認証・権限管理の追加が可能
- DB化（json-server → RDB）を前提にしたAPI分離
- D&Dライブラリ差し替え可能な境界設計

---

## 7. 実装優先順位（推奨）

1. 基本情報・休講日管理
2. 区分 → 講義（detail）
3. 1日ブロック
4. スケジュール（D&D＋自動割当）
5. 印刷（A4/PDF）

---

このモジュール設計は、  
**Word運用からWeb化し、休講変更に強いシステムを作る** という目的に最適化しています。
